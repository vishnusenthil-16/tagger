# Rust migration

The service and `tagger-smoke` CLI are Rust 2024 binaries. Build with the current stable Rust toolchain; local verification used Rust 1.99.1 on macOS ARM64. No earlier minimum Rust version is promised. `Cargo.lock` pins the dependency resolution.

## Preserved behavior

- `POST /v1/classify`, the JSON request/result/error shapes, and all `TAGGER_*` settings and defaults.
- Authentication before body reading; distinct client/backend keys; case-insensitive Bearer scheme and constant-time token comparison.
- Strict UTF-8 JSON, duplicate-key rejection at every nesting level, no unknown request fields, byte/count/ID limits, and validation before admission.
- Caller text/descriptions/order, the appended `__none__` option, raw scores, deterministic tie-breaking, separate confidence and model provenance.
- Jev `POST /v1/systemone`, including base URL prefixes, model selection, provider error mapping, and two-decimal score-sum tolerance.
- Incremental request/response byte caps; one deadline spanning upload and backend work; immediate overload without a queue, retry, redirect, proxy-env use, or fallback.
- Per-process capacity, cancellation of local upstream work on disconnect, sanitized outcome/timing logs, and no request-path or payload logging.

Tokio runs the asynchronous I/O. Hyper owns each HTTP/1 connection and its request future; dropping the connection drops backend work. A semaphore permit is held by that future and released by Rust ownership on success, failure, timeout, or cancellation. Reqwest uses verified Rustls TLS. No unsafe code is permitted in this crate; dependencies have their own implementations.

## Explicit migration differences

- Python imports (`tagger.app.create_app`, Pydantic models, ASGI middleware) and wheel packaging are removed. The supported boundary is the HTTP API and two executables, not a Rust library API.
- Malformed Unicode escapes, including lone surrogates, are rejected at JSON decoding with `422 invalid_request`; the Python field validator could return `invalid_text` or `invalid_category_description` for these. Valid Unicode still uses decoded UTF-8 byte limits.
- Malformed HTTP framing/header syntax can be rejected by Hyper before the service runs, with a transport-level response or closed connection rather than Tagger's JSON envelope. Header normalization also occurs at that boundary. Application-level errors retain the documented envelope.
- JSON nesting is bounded by the JSON parser. Excessively nested input is rejected rather than risking stack exhaustion.
- SIGINT/SIGTERM stops admission and cancels local connection tasks; shutdown does not wait for remote model completion. Cancellation cannot guarantee that a remote model stops computing.
- OpenAPI is a checked-in contract artifact, not generated by FastAPI. Tests check its endpoint, security, required response fields, and error statuses. Schema routes remain disabled.
- Optional `scripts/prepare_evaluation.py` and `scripts/run_live_smoke.py` remain standard-library Python tools. The latter now starts the built Rust binaries. Neither is required to run Tagger or its standalone smoke CLI.

## Validation

The black-box Rust suite starts the actual executable and a local synthetic HTTP provider on loopback. It exercises classification/no-match/ties, ordering/provenance, strict requests/authentication, UTF-8/body/category boundaries, all provider status mappings, malformed/oversized/compressed responses, confidence, unreachable providers, one/two-slot overload and recovery, total upload/backend deadlines, disconnect cancellation, startup errors, smoke CLI behavior, proxy-environment isolation, and log redaction. Tests do not use external credentials.

Local verification results:

Local commands:

```sh
cargo fmt --all --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked --all-targets
cargo doc --locked --no-deps
cargo build --locked --release --bins
cargo package --locked --target-dir target/package-check
python3 -m unittest discover -s evaluation/tests -v
```

For an uncommitted working tree, use `cargo package --locked --target-dir target/package-check --allow-dirty`; this still verifies the extracted source package builds. The package uses an explicit allowlist excluding private inputs, credentials, conversation attachments, and build outputs.

The Rust implementation has not been live-tested against Jev, deployed, published, or run in remote CI as part of this rewrite. Historical Python live results are not Rust verification or accuracy evidence. Linux and macOS CI/release jobs are configured; only the local platform has been executed here.
